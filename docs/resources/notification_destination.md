# irisbeat_notification_destination

```hcl
variable "alert_webhook_url" {
  type      = string
  sensitive = true
}

resource "irisbeat_notification_destination" "alerts" {
  channel     = "webhook"
  webhook_url = var.alert_webhook_url
}
```

## Schema

- `channel` (String, required) accepts `webhook` or `email`.
- `name` (String, optional) defaults to a name generated by Irisbeat.
- `webhook_url` (String, sensitive) is required for `webhook`.
- `email_address` (String, sensitive) is required for `email`.
- `id` (String, computed) is the opaque Irisbeat ID.
- `confirmed` (Boolean, computed) indicates whether the email recipient confirmed. Webhooks return `null`.

A rename preserves identity. Changing a channel or saved address replaces the destination. Deleting the destination clears all its Monitor assignments. Both CLIs can retain sensitive addresses in their plan and state files.

## Import

Declare matching configuration and run `terraform import irisbeat_notification_destination.alerts <destination-id>` or `tofu import irisbeat_notification_destination.alerts <destination-id>`.

## Email cutover

Install [email delivery](https://github.com/Webriot/irisbeat/blob/v0.5.0/docs/install.md#optional-email-confirmation) before adding an email destination.

1. Apply a second email destination with a distinct name and address while keeping the old destination assigned.
2. Have the recipient confirm the new inbox. Run `apply -refresh-only` and check `confirmed`.
3. Change the Monitor's `destination_ids` to use the new ID and apply while keeping both destination resources.
4. Remove the original destination from configuration and apply.
